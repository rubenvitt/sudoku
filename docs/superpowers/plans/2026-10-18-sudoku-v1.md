# Sudoku v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Klassisches 9×9-Sudoku für das iPad, mit Pencil gespielt, unendliche Rätsel in vier Stufen, Tipp, Überprüfen, Auswertung, Autosave — per CI öffentlich auf TestFlight.

**Architecture:** Reines Swift-Package `SudokuEngine` (Modell, Löser, Bewerter, Generator, Spielzustand) ohne UI-Abhängigkeiten, getestet mit `swift test`. Darüber eine schlanke SwiftUI-App (Menü, Spiel, Auswertung) mit PencilKit-Eingabe; Spielstand als JSON-Datei. GitHub Actions testet jeden Push und lädt `main` nach TestFlight.

**Tech Stack:** Swift 6 (strict concurrency), SwiftUI, PencilKit, Vision/Core ML (je nach Spike), xcodegen, GitHub Actions, fastlane pilot.

**Spec:** `docs/superpowers/specs/2026-10-18-sudoku-design.md`

**Zunder:** Jede Task ist eine Aufgabe im Zunder-Projekt „Sudoku" (Schlüssel `SUDOKU`, Task n = `SUDOKU-(n+1)`); die Abhängigkeiten unten sind dort als `blocked_by` gesetzt. Beim Start `claim_task`, Branch/PR an der Aufgabe festhalten.

## Global Constraints

- iPadOS-Deployment-Target **26.0**, `TARGETED_DEVICE_FAMILY = 2` (nur iPad), Hoch- und Querformat.
- Swift 6, `SWIFT_STRICT_CONCURRENCY = complete`.
- Bundle-ID **`dev.rubeen.sudoku`**, Homescreen-Name **„Sudoku"**, `ITSAppUsesNonExemptEncryption = NO`.
- `SudokuEngine` importiert weder SwiftUI noch UIKit noch PencilKit.
- Keine Fremd-Abhängigkeiten in App und Engine (fastlane nur in der CI, dort vorinstalliert).
- Zielhardware: Logitech Crayon, iPad 2020/21 (A12–A14). Kein Hover, Doppeltipp, Squeeze, Druck voraussetzen.
- Repo ist **öffentlich**: keine Secrets, keine `.p8`, keine Handschriftproben von Ruben im Repo.
- Code, Bezeichner, Dateien englisch; Oberflächentexte, Tipp-Texte, Doku deutsch mit echten Umlauten.
- Stufen: `easy` „Leicht", `medium` „Mittel", `hard` „Schwer", `expert` „Experte".
- Fehler werden nie ungefragt angezeigt — nur nach „Überprüfen" oder bei vollem Gitter.

## Review Focus

1. **Abbruch mitten im Schreiben / kaputte Spielstand-Datei** → App startet trotzdem ins Menü, ohne „Weiterspielen", stürzt nie ab. Test in Task 5 (`testLoadReturnsNilForCorruptFile`).
2. **Strich über Zellgrenzen oder auf einer vorgegebenen Zelle** → Strich gehört der Zelle unter der Mitte seiner Bounding-Box; auf Givens wird er verworfen, nichts ändert sich. Test in Task 10 (`testStrokeAssignedToCellOfBoundingBoxCenter`, `testStrokeOnGivenIsDiscarded`).
3. **Schnelles Mehrfach-Starten von „Experte"** (Vorrat leer) → UI blockiert nie; Ladeindikator nur bei leerem Vorrat, Generierung läuft im Hintergrund. Test in Task 5 (`testStockRefillsAfterTake`).
4. **Undo nach „Überprüfen"** → eine rot markierte Zelle, die per Undo geändert wird, verliert ihre Markierung; Markierungen tauchen durch Undo/Redo nie wieder auf. Test in Task 4 (`testUndoClearsErrorMark`).
5. **Tipp bei falscher Eingabe / nur falschen Notizen** → falsche Ziffer: Hinweis nennt die Zeile, nicht die Zelle; Notizen werden für den Tipp ignoriert. Test in Task 4 (`testHintReportsWrongEntryRow`, `testHintIgnoresNotes`).

### Task 2: Engine — Bewerter und Techniken

**Files:**
- Create: `Sources/SudokuEngine/{Techniques,Grader}.swift`
- Test: `Tests/SudokuEngineTests/GraderTests.swift`

**Interfaces:**
- Consumes: `Variant`, `Grid`, `CandidateMask`, `candidates(for:in:)` (Task 1)
- Produces:
  - `public enum Difficulty: String, Codable, CaseIterable, Sendable { case easy, medium, hard, expert; public var title: String /* "Leicht" … "Experte" */ }`
  - `public enum Technique: Int, Comparable, Sendable { case nakedSingle, hiddenSingle, intersection, nakedPair, hiddenPair, nakedTriple, xWing, swordfish, xyWing; public var difficulty: Difficulty }`
  - `public struct Step: Sendable { public let technique: Technique; public let placement: (cell: Int, digit: Int)?; public let eliminations: [(cell: Int, digit: Int)]; public let focus: [Int]; public let explanation: String }`
  - `public enum Grader { static func nextStep(_ grid: Grid, candidates: [CandidateMask], in variant: Variant) -> Step?; static func grade(_ puzzle: Grid, in variant: Variant) -> Difficulty? /* nil = nicht ohne Raten lösbar */ }`

Zuordnung (Spec §4.1): Singles → easy; `intersection` (deckt Pointing und Box-Line generisch ab: liegen alle Kandidaten d einer Gruppe A in Gruppe B, streiche d aus B∖A) → medium; Pairs/Triple → hard; `xWing`, `swordfish` (über `rows`/`columns`), `xyWing` (über `peers`) → expert. `nextStep` probiert Techniken in Enum-Reihenfolge, liefert die erste anwendbare. `grade` wendet Schritte bis gelöst an; Stufe = Maximum der benutzten Techniken. Erklärungen deutsch, Zeilen/Spalten 1-basiert, z. B. „In Zeile 4 passt die 7 nur noch in Spalte 2."

### Task 4: Engine — Spielzustand

**Files:**
- Create: `Sources/SudokuEngine/Game.swift`
- Test: `Tests/SudokuEngineTests/GameTests.swift`

**Interfaces:**
- Consumes: `Puzzle`, `Grader.nextStep`, `candidates(for:in:)`
- Produces:
  - `public struct Game: Codable, Sendable { public let puzzle: Puzzle; public private(set) var entries: Grid; public private(set) var notes: [CandidateMask]; public private(set) var errorMarks: Set<Int>; public var elapsed: TimeInterval; public private(set) var hintsUsed: Int; public private(set) var checksUsed: Int; public private(set) var errorsFound: Int; public init(puzzle: Puzzle) }`
  - Mutationen (no-op auf Givens): `mutating func setDigit(_ d: Int, at cell: Int)`, `mutating func toggleNote(_ d: Int, at cell: Int)`, `mutating func clear(_ cell: Int)`, `mutating func undo()`, `mutating func redo()`; `var canUndo: Bool`, `var canRedo: Bool`
  - `mutating func check() -> Set<Int>` (falsche Einträge, setzt `errorMarks`, zählt `checksUsed`, `errorsFound += count`)
  - `var isSolved: Bool`; `var isFull: Bool`
  - `mutating func hint() -> Hint?` mit `public enum Hint: Sendable { case wrongEntry(row: Int) /* 1-basiert */; case step(Step) }` — zählt `hintsUsed`, `nil` wenn gelöst.

Regeln: `setDigit` löscht Notizen der Zelle und entfernt die Ziffer aus den Notizen der `peers`; jede Änderung an einer Zelle entfernt deren `errorMark`. Undo-Verlauf = Stack von Snapshots `(entries, notes)`; Undo/Redo entfernen `errorMarks` aller dabei geänderten Zellen. Gleiche Ziffer erneut setzen = löschen (Toggle).

### Task 6: Oberfläche mit Finger-Eingabe

**Files:**
- Create: `Sudoku/UI/{MenuView,GameView,GridView,NumberBar,ResultView}.swift`
- Test: `SudokuUITests/SmokeTests.swift`

**Interfaces:**
- Consumes: `Game`, `Store`, `PuzzleStock`, `Difficulty.title`, `Hint`, `Step.focus/explanation`
- Produces: `GridView(game: Game, selection: Binding<Int?>, onCellFrame: …)` mit stabilen Zell-Frames im Koordinatenraum `"grid"` — Task 10 legt darüber das Pencil-Overlay; `GameView` hält `@State var game: Game` und `var noteMode: Bool`, bietet `func apply(_ input: CellInput)` mit `enum CellInput { case digit(Int, cell: Int); case note(Int, cell: Int); case clear(cell: Int) }`.

Verhalten (Spec §6):
- **Menü:** „Weiterspielen" (Stufe + Zeit) falls `store.loadGame() != nil`; Art „Klassisch" als (einzeilige) Liste; vier große Stufen-Buttons. Tippen startet sofort; läuft ein Spiel, `confirmationDialog` „Aktuelles Spiel verwerfen?".
- **Spiel:** Gitter maximal groß (quadratisch, `GeometryReader`), 3×3-Kästen dicker umrandet; Auswahl hebt Zeile/Spalte/Kasten und gleiche Ziffern dezent hervor; Notizen im festen 3×3-Raster; `errorMarks` rot. Leiste: Zeit, Undo, Redo, Notizmodus, Tipp, Überprüfen, Menü. `NumberBar` 1–9 + Löschen für Finger/VoiceOver. Tipp: `.wrongEntry` → Banner „In Zeile N stimmt etwas nicht."; `.step` → `focus`-Zellen hervorheben + `explanation` als Banner. Nach jeder Mutation `store.save(game)`. Timer zählt nur bei `scenePhase == .active`.
- **Auswertung:** sobald `isSolved` → `ResultView` (Stufe, Zeit, Tipps, Prüfungen, gefundene Fehler; „Neues Spiel" gleiche Stufe, „Menü"), Spielstand löschen. `isFull && !isSolved` → automatisch `check()`.
- Haptik (`sensoryFeedback`) bei gesetzter Ziffer und beim Abschluss.
- Zwei-Finger-Tipp aufs Gitter = Undo (Spec §5).
- Barrierefreiheit: jede Zelle `accessibilityLabel` „Zeile r, Spalte c, Wert/leer".

### Task 10: Pencil-Eingabe

**Files:**
- Create: `Sudoku/Input/{PencilCanvas,StrokeRouter,DigitRecognizer}.swift` (+ ggf. `Digits.mlmodel` aus dem Spike)
- Modify: `Sudoku/UI/GameView.swift` (Overlay einhängen)
- Test: `SudokuTests/StrokeRouterTests.swift`

**Interfaces:**
- Consumes: `DigitRecognizer` + Gewinner (Task 0), `GameView.apply(_ input: CellInput)`, Zell-Frames aus `GridView` (Task 6)
- Produces:
  - `struct StrokeRouter { let gridFrame: CGRect; let givens: Set<Int>; func cell(for strokeBounds: CGRect) -> Int?; func isNote(_ strokeBounds: CGRect) -> Bool; func isScratchOut(_ points: [CGPoint]) -> Bool }` — reine Geometrie, keine PencilKit-Typen.
  - `PencilCanvas: UIViewRepresentable` — transparentes `PKCanvasView`, `drawingPolicy = .pencilOnly` (Finger gehen an das Gitter darunter), sammelt Striche je Zelle, 0,4 s nach dem letzten Strich: Durchkritzeln → `.clear`; sonst Erkenner → `.digit`/`.note` (Notiz bei `isNote` oder aktivem Notizmodus); danach Striche der Zelle aus dem Canvas entfernen.

Regeln: Zelle = Zelle unter der Mitte der Bounding-Box aller Striche der Zelle; Strich auf Given → verwerfen; Notiz-Schwelle Höhe < 0,5 × Zellhöhe (nur wenn der Spike die Größenregel bestätigt hat, sonst `isNote` immer `false`); Durchkritzeln = Pfadlänge > 4 × Breite der Bounding-Box und ≥ 3 Richtungswechsel in x. Erkennung `nil` oder unter Konfidenzschwelle → Striche bleiben 1 s sichtbar grau und verschwinden, keine Eingabe.

- [ ] **Step 1: Failing tests**

```swift

func testStrokeOnGivenIsDiscarded()                   // cell(for:) == nil
func testSmallStrokeIsNote()                          // Höhe 0,3 × Zelle → true; 0,7 → false
func testZigZagIsScratchOut()                         // Zickzack-Punkte → true; eine „7" → false
```

- [ ] **Step 2:** Tests → FAIL.
- [ ] **Step 3:** Implementieren; Erkenner aus dem Spike übernehmen.
- [ ] **Step 4:** Tests → PASS; auf Rubens iPad mit dem Crayon ein leichtes Rätsel komplett per Stift lösen (Ziffern, Notizen, Durchkritzeln), Latenz subjektiv ohne Hänger.
